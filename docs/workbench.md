# 本地研究工作台

## 架构

`trading.workbench` 是独立的本地展示层。FastAPI 只绑定 `127.0.0.1`，静态 HTML/CSS/JavaScript 不依赖外部 CDN。页面经固定 API 读取版本化 Parquet、质量 JSON、研究报告和 YAML 候选配置。工作台不导入 `trading.execution`，也没有订单、账户或实盘 HTTP 路由。

页面分为总览、数据工厂、因子与策略、研究运行、模拟执行、数据路线六个视图。策略和因子表展示既有目录报告的样本外指标及校正后的 p 值；显著因子与可盈利策略明确区分。执行视图只显示参数准备状态和风险门槛，不将研究结果解释为交易指令。

## 关键设计决策

- 运行入口：`python -m trading` 与 `trading workbench` 启动工作台；既有 CLI 子命令保持可用。
- 写入操作：只允许环境检查、固定 BTC 数据采集、固定四资产采集、Coinbase 60 秒 Level 2 录制、Coinbase 单次盘口快照、单资产研究、目录研究七种后台任务；不接收任意命令、脚本或文件路径。任务串行、最长一小时、最近 20 次状态保存在进程内。
- 浏览器任务请求需携带进程生成的随机令牌；令牌放在首页元数据中。限制 Host，并仅监听 loopback。此设计适合单用户本机使用，不用于局域网或公网部署。
- 报告和数据由本地现有文件动态发现；无数据或无报告时页面显示空状态。研究产物仍按原有规则不提交 Git。
- 价格图只采样本地收盘价用于观察；未计算成交信号或回测收益。
- 数据视图展示盘口会话的消息、快照、更新、中断与质量状态。HTTP 单次快照单独标记，不作为连续历史展示。

## 如何运行

工程根目录：

```bash
uv sync --locked --extra research
uv run python -m trading
# 或：uv run trading workbench --port 8765
```

浏览器打开 `http://127.0.0.1:8765`。`Ctrl+C` 停止。若只看数据与报告，`uv sync --locked` 即可；运行单资产和目录研究需安装 `research` extra：

```bash
uv sync --locked --extra research
uv run trading workbench --port 8765
```

工作流：先看数据质量，再按预先固定的配置启动研究任务，等待状态完成，复核报告的成本、样本外区间、多重检验和限制。修改实验假设时应新建版本，不覆盖已看过保留集的预声明。

## 潜在风险与限制

- 工作台状态和任务日志在内存中；进程重启后任务历史消失，正式研究证据仍在 `research/runs`。运行中的子进程可能在浏览器关闭后继续执行，需查看终端状态。
- 一小时超时只约束单个后台任务。大量新资产时，数据目录清单扫描将需要增量索引或数据库元数据表。
- 任务继承启动进程环境；本机只运行受控命令，但应继续保持 API 密钥在 `.env` 或系统凭据中，不向页面暴露。
- 模拟盘配置仍有空值，实盘继续禁用。工作台的任务按钮不启动模拟或实盘下单。
- 多资产固定样本池是回溯选择的工程样本；Coinbase Advanced Trade 在线 60 秒录制已通过，但仍需长期稳定性验收。Coinbase HTTPS 单次快照不提供过去的盘口增量。
